Home page search: decisions

Sample data. The look is our portal skin (slate and #E11D48), not another site's brand. Taken already (2026-11-24): all 6 tabs, the Filters panel is back, the AI toggle (On = guide, Off = normal search), mock first.

  1. Several suburbs in one search. Each place you pick becomes a chip, up to 10. Results = listings in ANY of them. recommended
    The URL gains a repeatable loc=Pakenham|VIC|3810. Old links, saved searches and alerts with a single suburb= keep working unchanged. A saved search and an alert can then hold several suburbs, which changes packages/core (search, saved search, alert matching) but needs no migration (saved queries are JSON).
  2. Distance applies to every chosen suburb. "Pakenham + Berwick, within 10 km" = both suburbs, plus anything within 10 km of either one. Options: Only these suburbs (default), 2, 5, 10, 20, 50 km. recommended
    Each suburb's centre still comes from the server (place_cache), never the browser, the same rule as today.
  3. Typing "within 10 km of Pakenham" works without the AI. A small parser in the box reads within N km of / N km from / N km around, sets the distance, and looks up the rest as the place. recommended
    "10 mins walk from" is not offered: we have no travel-time data, and a straight-line guess would be wrong. The box says so and offers the km version.
  4. Recent searches are kept in the browser (the last 5, on this device). recommended
    This keeps / a cached page (33 ms): reading a session would make it render per visitor. Saved searches for signed-in users are unchanged.
  5. Address tab: pin-point. Pick a street address. If we have that property, it opens its page (/property/[id]: history, sold and listed). If we don't, it shows homes for sale within 2 km of that point. recommended
  6. Agents tab: a new public page /agents. Search by suburb (or agent or agency name). It lists agents of active agencies who have live or sold listings there. Every count comes from SQL: for sale now, sold in 12 months, median days on market. recommended
    It shows only what a listing already shows publicly (name, photo, agency, the listing phone). No ranking score. A blocked or removed member never appears. It needs a new core query and a permission test.
  7. Build tab ("New homes"). We have no "new home" data today. Choose one:
    What it showsCost
    A recommendedA new tick on the listing form, "New home / house-and-land / off the plan" (listing.is_new_build). The Build tab shows only listings with that tick.One additive column (dev first, production on your go), one checkbox in the console form
    BNo new field. Build = land for sale + homes built in the last 2 years (year_built)No migration, but it will show old homes with a wrong year and miss off-the-plan listings
  8. Filters panel: property type (multi), price min/max (sale prices, or per week for Rent), bedrooms, bathrooms, car spaces. It writes the same URL parameters as today (beds, baths, cars, type, priceFrom, priceTo), so links and alerts don't break. The button shows how many are set ("Filters · 3").
    Several property types needs type to repeat in the URL. The saved query already stores propertyTypes[].
  9. AI toggle under the box, default Off. On: the same box takes a sentence and opens the guide (/chat?ask=…), exactly as the current home box does. The floating "Ask AI" button bottom-right opens the guide too.
  10. Below the box: "Explore" tiles for pages we already have (Affordability, Suburb profiles, Recently sold), then the "Latest listings" grid as today. No news section: we have no news.

Order of building after approval: (1) core: several suburbs + distance per suburb, with tests. (2) the home page box: tabs, chips, distance, filters, recent searches, AI toggle. (3) the same box on /search and /sold. (4) Address pin-point. (5) /agents. (6) Build (A or B). Each part goes on a dev branch; production in one go at the end, on your go.
